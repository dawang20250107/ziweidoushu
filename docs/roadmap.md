# 产品与技术路线图(v2,已拍板)

> 定位:基于倪海厦《天纪》体系的 AI+ 紫微斗数平台。
> 产品标准:科技风格、对标硅谷顶尖 SaaS、深度移动端适配、面向市场的顶尖产品级别。
> **主攻方向(v2 明确):排盘做精做透 + 古籍阅读顶级丝滑。二者构成一个闭环,是产品的全部重心。**

## 已拍板的技术决策

| 决策项 | 结论 | 核心理由 |
|--------|------|----------|
| 后端 | Go(已完成重构) | 高并发原生、单二进制部署、lunar-go 历法与基准同源 |
| 前端 | **Next.js 15 + React 19 + TypeScript + Tailwind CSS 4 + shadcn/ui + Framer Motion** | 顶级 SaaS 设计生态、SSR 利于 SEO、自建设计系统 |
| 数据库 | **PostgreSQL 16(唯一事实源)+ Redis 7(共享态)** | 支付事务、JSONB 命盘快照、pgvector 做 RAG;Redis 做限流/会话/队列 |
| 古籍语料 | 保持内存快照 + 二元索引(不入库) | 读多写少,现有方案即最优 |
| 代码组织 | **Monorepo**:根为 Go API,新增 `web/`(Next.js) | 类型契约同仓同步,一处审查 |
| 目标市场 | **先国内** | 手机号+微信登录;微信/支付宝支付;海外(Stripe/多语言)二期开关预留 |
| 小程序 | **暂缓,只保接口**:API 层维持纯 JSON+SSE 契约,Web 做移动优先响应式+PWA;后期用 Taro 直接接同一套接口 | 不是当前主攻方向,现在零投入 |

## 核心体验一:排盘做精做透

### 视觉层(星盘即产品记忆点)
- 十二宫 + 中宫命主信息的经典布局,现代设计语言重做
- 星曜按主星/辅星/杂曜分层级排布;庙旺利陷用色彩语义;四化标记+连线
- 三方四正联动高亮;暗色星空底 + 微动效(星曜入盘、宫位聚焦)

### 交互层(专业工具手感)
- 点宫位 → 侧栏宫位详情(星曜解释、格局关联、借宫说明)
- 点星曜 → 星曜知识卡(倪师体系描述 + 古籍出处直达)
- **时间轴下钻:本命盘 → 大限盘 → 流年盘 → 流月盘**,时间轴拖动切换,运限星曜叠加显示(后端需新增运限叠加 API,流曜安星规格见 docs/algorithm/)
- 显示密度三档:简洁(小白)/ 专业(主星+四化+格局)/ 大师(全星曜+十二神)
- 选中宫位/格局一键追问 AI(排盘与 AI 对话一体,不是两个页面)

### 严谨层(信任感即差异化)
- 真太阳时校正过程可视化(校正分钟数与原因)
- 闰月折算说明;每个格局标注古籍出处
- 「算得有依据」= 对标顶级产品的信任差异点

## 核心体验二:古籍阅读顶级丝滑

1. **排版即体验**:顶级中文排版(思源宋体/霞鹜文楷、字号行距留白讲究)、纸质/暗色/护眼三主题、字号调节;全章节 SSG 预渲染 + 下一章预取,零 loading 感
2. **三层文本结构**:原文 / 白话翻译 / 倪师注解 一键切换或对照(数据结构已支持:`translation`/`niNote` 字段)
3. **划词即问**:选中古文 → 浮层 AI 解释(携带该段上下文);段落级锚点、毫秒级即时检索、命中高亮跳转
4. **双向联动(闭环)**:古籍中星曜名 → 跳转自己命盘对应宫位;AI 解读引用的古籍段落 → 一键回原文上下文

## 产品矩阵(围绕客户粘性)

### 引流层(免费,获客与 SEO)
- 排盘工作台、基础格局判定、古籍阅读与全文检索
- 主星×主题知识页(SEO 静态页矩阵)、命盘分享卡片

### 粘性层(回访与锁定)
- **AI 命理对话**:记住命盘与历史对话的持续咨询(AI+ 差异化本体)
- **命盘档案库**:保存家人朋友命盘(数据锁定)
- **合盘**:恋爱/合伙契合度(双人传播、关系链)

### 变现层(订阅)
- 深度主题报告(事业/婚恋/健康)、年度运势报告(春节续费节点)
- 倪师体系精读:天纪课程学习路径 + 古籍逐段倪师注解(内容护城河,待资料到位)

### 会员分层
| 层级 | 内容 |
|------|------|
| 免费 | 排盘、基础格局、古籍阅读检索、有限 AI 解读(免费层必须好用——获客靠它) |
| Pro 订阅 | AI 无限对话、运限盘全量下钻、合盘、档案无限、深度报告 |
| 大师版 | 更强模型、专属深度报告、(预留)真人咨询对接 |

## 注册 / 支付(国内口径)

- **注册登录**:手机号+短信验证码为主;微信登录(Web 扫码),UnionID 口径预留小程序;JWT 双 token + Redis 会话版本控制
- **支付**:微信支付(Web Native 扫码,JSAPI 接口预留)、支付宝(Web/H5);订阅为**周期购买制**(1/3/12 月)+ 到期提醒;订单状态机 + webhook 幂等 + 每日对账
- 海外:Stripe / Apple / Google 登录,二期以 feature flag 预留

## 平台必备

1. **管理后台**:内容/用户/订单管理、AI 成本看板(同 Next.js 栈)
2. **合规**:命理内容定位「传统文化/娱乐参考」+ 全站免责声明;出生数据按 PIPL 保护
3. **观测与 CI/CD**:GitHub Actions 测试门禁(黄金基准回归全绿才可合并)、Sentry、Prometheus/Grafana
4. **AI 成本治理**:按会员层级路由模型 + 解读缓存 + 每用户配额

## 分阶段执行(协作模式:Fable 5 架构/关键实现/验收,Opus 4.8 执行)

| 阶段 | 交付 | 关键活(Fable 亲自) | 执行活(Opus) |
|------|------|---------------------|---------------|
| P0 | 设计系统、DB Schema、鉴权/支付架构、**运限叠加引擎设计** | 全部(不可逆决策) | — |
| P1 | **排盘工作台(含时间轴运限下钻)+ 古籍阅读器**、注册登录、AI 对话 | 运限安星引擎(需新基准校验)、星盘核心组件、鉴权 | 页面与组件批量实现、测试、知识卡内容装配 |
| P2 | 订阅+支付、档案库、合盘、深度报告 | 支付状态机 | 报告模板、页面实现 |
| P3 | 古籍精读/倪师注解层(待资料)、年度报告、增长功能 | 语料质量验收 | 内容批量结构化 |

**执行纪律**:任务派发前先立机器可验收标准(测试/契约/基准);出错不可逆或影响全局的由 Fable 亲自做;委派产出至少过一道独立校验。
