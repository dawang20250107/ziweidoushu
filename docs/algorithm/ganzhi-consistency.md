# 干支基础表跨引擎一致性审计

日期:2026-07-18。范围:六爻(`internal/liuyao`)、大六壬
(`internal/daliuren`)、四柱视角(`internal/ziwei/sizhu.go`)三处
共用的干支/五行基础常量。

## 核对结论:三处口径完全一致,零冲突

| 常量 | 值 | 出现处 |
|---|---|---|
| 地支序 `branches` | 子丑寅卯辰巳午未申酉戌亥 | liuyao / daliuren / sizhu(szBranches)/ ziwei.Branches |
| 天干序 `stems` | 甲乙丙丁戊己庚辛壬癸 | 同上 |
| 地支五行 `branchElement` | {4,2,0,0,2,1,1,2,3,3,2,4}(子水始) | liuyao / daliuren / sizhu **逐字相同** |
| 五行名 `elementNames` | 木0 火1 土2 金3 水4 | liuyao / sizhu(daliuren 用索引不列名) |
| 相生 / 相克 | `(x+1)%5` / `(x+2)%5` | 三处公式一致 |

各引擎独有的领域表(六爻六合/纳甲、大六壬驿马/寄宫/刑、四柱藏干/纳音/
禄刃)为专属,无重复、无交叉,不存在口径分叉风险。

## 设计决策:刻意各自持有,不提取公共包

**不抽取 `internal/ganzhi` 公共基础包**,理由:

1. **表极稳定**:干支五行几千年不变,重复的维护成本≈0,无 drift 动机;
2. **解耦优先**:核心紫微引擎有 1566 例黄金基准,不宜为省几行常量引入
   对新公共包的编译依赖;三引擎当前互不依赖,是干净的边界;
3. **已有更强保护**:每个引擎的基础表由**其自身黄金基准间接锁定**——
   改错 `branchElement`,该引擎的回归测试(六爻 377 占例 / 四柱纳音十神 /
   大六壬 17280 冒烟)立即失败。这比"为测试而导出内部常量的跨包一致性
   测试"更可靠,且不污染 API。

三处基础表已加同步注释,把"故意重复、须同步"的隐性约定变为显性。

## 复核方式

`grep -rn 'branchElement = \[\]int' internal/{liuyao,daliuren,ziwei}` 应
三处同值;各引擎 `go test` 全绿即保证各自表正确。
